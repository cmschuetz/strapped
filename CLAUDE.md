# Guidelines

- **Run the prompt-eval suite alongside `bun test` when changing harness prompts.** When you edit an agent prompt — anything under `src/workflows/strapped-run/**` or the step prose in a skill `SKILL.md` — run `bun run eval --suite <dir>` (see `src/eval/` and the "Prompt evaluation suite" section of `CONTRIBUTING.md`) and keep it green alongside `bun test`. The eval suite grades a prompt on correctness / cost / latency through `claude -p`; it is the evidence that a prompt change is a real improvement (use `--ab` to compare a baseline vs a candidate and gate on a correctness regression past `--tolerance`). It is a HEAVY, opt-in layer (needs a real `claude` + spends cost), so it is intentionally NOT part of `bun test` — run it yourself for prompt work. `bun test` stays hermetic/offline and remains the gate for everything else. The suite also carries **scenario evals** (`src/eval/scenarios/harness/`) — full workflow runs (plan → implement → pr, or any stage subset) against a sandboxed fixture repo, graded on correctness/adherence/time/price. Run `bun run eval --scenarios src/eval/scenarios/harness` when changing WORKFLOW behavior (stage logic, budgets, orchestration); save `--json` reports before and after the change and gate with `bun run eval --compare <baseline.json> <candidate.json>` — that offline comparison is the evidence that a workflow change is an improvement. Scenarios are far heavier than prompt cases: every agent call is a real multi-turn agentic `claude -p` run, so expect minutes of wall clock and real dollars PER SCENARIO.

- **Bump the plugin version with the tool, never by hand.** `claude plugin update` compares `version` in `plugins/strapped/.claude-plugin/plugin.json` only — an unbumped version leaves installed copies silently pinned to a stale commit after a change merges. Bump ONLY via `bun tools/version.ts bump <major|minor|patch>` (it rewrites the one semver deterministically); do not hand-edit plugin.json. Pick the level by a conventional-commit rule: a breaking change → `major`, a new user-facing feature (skill/workflow/script behavior) → `minor`, a fix or internal change → `patch`. Before committing, run `bun tools/version.ts check` (alias `bun run version:check`) — it fails when a changed *generated artifact* (the committed deployables under `plugins/strapped/`) is not accompanied by a version bump above the base. Prompt/skill/docs-only changes with NO generated-artifact change are at your discretion — the guard exits 0 for them, so bump when the change is user-facing and skip an internal-only tweak.
